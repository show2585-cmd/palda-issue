U-01

아이콘을 화면마다 따로 그려 선 두께가 제각각

높음

공통 아이콘 세트 없이 SVG를 JSX에 직접 넣었습니다. 같은 24×24 아이콘인데 선 두께가 네 가지라 화면을 옮길 때마다 아이콘의 무게감이 달라집니다.

근거
  • 아이콘 라이브러리(lucide, heroicons, Material 등)를 쓰지 않음
  • viewBox="0 0 24 24" 인라인 SVG 30개, 공통 *Icon 컴포넌트 이름 규칙 없음

사용자 영향

사이드바·카드·버튼의 아이콘 굵기가 서로 달라 화면이 정돈되지 않아 보이고, 같은 뜻의 아이콘이 화면마다 다르게 그려질 수 있습니다.

개선 방향
  • lucide-react 도입: 지금 아이콘과 같은 24×24 그리드, currentColor, 둥근 선 끝이라 바꾸기 쉽고 쓰는 아이콘만 번들에 들어감
  • <Icon name size="sm|md|lg" /> 래퍼로 크기와 선 두께를 디자인 토큰에 묶기 (예: 기본 1.5 하나로 통일)
  • 브랜드·플랫폼 로고(/brand/*.svg)는 지금처럼 별도 에셋 유지
U-02

데이터 화면에 10px 글자가 너무 많음

높음

글자 크기 토큰에 --palda-font-size-2xs: 10px가 있고, 숫자를 읽어야 하는 키워드·상품 화면의 보조 라벨이 대부분 이 크기입니다.

근거
  • 키워드 상세(종합 분석) 본문 텍스트 요소 181개 중 10px이 31개(17%), 12px이 83개
  • CSS 전체에서 2xs(10px) 토큰 37회 사용, 별도로 font-size:9px도 1곳 존재
  • 상품 분석 목록의 가격 · 6개월 판매량 · 6개월 매출 · 리뷰 · 평점 · 등록일 라벨이 10px
사용자 영향

한글 10px은 획이 뭉쳐 읽기 어렵고, 이 서비스의 주 사용자인 셀러는 숫자를 오래 비교하는 작업을 합니다. 노안이나 저해상도 모니터에서는 사실상 확대 없이 읽기 힘듭니다.

개선 방향
  • 본문·라벨 최소 크기를 12px로 올리고 2xs 토큰은 배지·차트 눈금 정도로만 제한
  • 정보 위계는 크기 대신 굵기·색(text-primary-sub)으로 표현
U-03

알림톡(iframe) 화면은 폰트부터 달라 다른 서비스처럼 보임

높음

알림톡 체험(/alimtalk)은 별도 앱(/crm/)을 iframe으로 불러옵니다. 그런데 이 앱에서는 Pretendard가 제대로 적용되지 않아, 화면 글자 대부분이 Windows 기본 글꼴(맑은 고딕)로 보입니다. 바로 위 체험 바는 Pretendard라서 한 화면 안에서 글꼴이 두 가지입니다.

근거 (실제 화면에서 측정)
  • iframe 안 텍스트 요소 167개 중 133개(80%)가 font-family: Pretendard, system-ui, …
  • CDN으로 불러온 글꼴 이름은 "Pretendard Variable" 하나뿐이고, "Pretendard"라는 이름의 글꼴은 정의되지 않음 → 다음 후보인 system-ui(맑은 고딕)로 넘어감
  • 같은 문장의 렌더링 너비가 Pretendard 지정 278.3px = 맑은 고딕 278.3px, Pretendard Variable은 241.4px. 실제로 다른 글꼴이 쓰이고 있음
  • 원인은 토큰 값 차이: 메인 앱 CSS에는 --palda-font-family-base가 두 번 정의돼 뒤쪽 값 "Pretendard Variable", Pretendard, …가 적용되지만, 알림톡 앱에는 앞쪽 값 Pretendard, system-ui, …만 들어 있음
  • Tailwind 기본값 html { font-family: -apple-system, "Segoe UI", Roboto, … }도 남아 있어, palda 토큰·--font-body·Tailwind 기본값 세 가지가 섞여 있음

사용자 영향

키워드에서 알림톡으로 넘어가는 순간 글꼴, 헤더, 메뉴가 한꺼번에 바뀌어 다른 사이트로 이동한 것처럼 느껴집니다. 글꼴이 OS마다 다르게 보이므로 Windows와 Mac 사용자가 보는 화면도 서로 다릅니다.

개선 방향
  • 당장: 알림톡 앱의 --palda-font-family-base를 메인 앱과 같은 "Pretendard Variable", Pretendard, …로 맞추고, Tailwind --font-sans도 이 토큰으로 연결
  • 근본: 두 앱이 같은 토큰 패키지를 쓰도록 바꾸고, 가능하면 iframe을 없애 한 앱의 라우트로 합치기 (코드 기술 T-01)
U-04

모바일에서 키워드 상세·상품·판매자 분석을 막아 둠

중간

좁은 화면에서는 기능 대신 "PC에서 이용해 주세요" 안내가 뜨고, 키워드 트렌드만 볼 수 있습니다. 랜딩의 키워드 검색창도 모바일에서는 안내 문구로 바뀝니다.

근거
  • 번들 문구: "키워드 상세·순위 추적·상품·판매자 분석은 PC에서 제공됩니다."
  • 정작 서비스가 보여 주는 샘플 데이터(휴대용 에어컨)도 검색 사용자 모바일 88% / PC 12%
사용자 영향

이동 중에 "이 키워드 검색량만 확인"하려는 셀러는 할 수 있는 일이 없습니다. 메신저로 받은 분석 링크를 휴대폰에서 열면 바로 막힙니다.

개선 방향
  • 전부 막기보다 요약 지표(검색량·경쟁강도·CPC)와 추이 차트만이라도 읽기 전용으로 제공
  • 표는 모바일에서 카드형으로 바꾸고, 깊은 분석만 "PC에서 더 보기"로 안내
U-05

페이지 번호를 눌러도 목록 맨 위로 돌아가지 않음

중간

상품 분석의 "네이버 TOP 30 상품" 목록은 10개씩 3페이지로 나뉩니다. 맨 아래 페이지 번호를 누르면 내용만 바뀌고 스크롤은 그대로라, 새 페이지의 중간부터 보게 됩니다.

근거 (실제 화면에서 측정)
  • 페이지 버튼을 누르기 전과 후의 스크롤 위치가 1332px로 같음
  • 누른 뒤 목록 영역(.npr-section)의 위쪽 끝이 화면보다 408px 위에 있음. 목록 제목과 11~13번 상품이 보이지 않음
  • 페이지 번호가 주소(?page=)에 남지 않아, 새로고침하거나 상품을 봤다가 뒤로 가면 1페이지로 돌아감
사용자 영향

2페이지를 눌렀는데 14번부터 보이니 "11~13번이 빠졌나?" 하고 다시 위로 스크롤해야 합니다. 페이지를 넘길 때마다 같은 동작이 반복됩니다.

개선 방향
  • 페이지를 바꾸면 목록 제목 위치로 스크롤하고, 고정 헤더가 있으면 scroll-margin-top으로 높이만큼 띄우기
  • 페이지 번호를 URL 쿼리(?page=2)에 남겨 새로고침과 뒤로 가기에도 유지
  • 같은 페이지네이션을 쓰는 다른 목록에도 공통 컴포넌트로 일괄 적용
